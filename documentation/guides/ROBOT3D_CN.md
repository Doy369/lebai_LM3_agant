# Lebai 三维预览集成与验证

本地后端控制台 `/ui/` 与 GitHub Pages `docs/` 共用三维模块，保留原有控制台功能。三维预览不发送运动请求，不改变控制令牌、真机使能或探测锁权限。

## 运行

在线预览：https://doy369.github.io/lebai_LM3_agant/ 。默认仅运行静态三维功能，不访问后端。手动预览、夹爪动画、轨迹、虚拟摄像头和场景保存均可独立使用。需要接口功能时先填写后端地址并启用“后端连接”；HTTPS/HTTP、跨域与本地网络访问限制可能阻止请求，优先使用本地 `/ui/`。实时模式未连接时明确显示断开，不生成模拟真机状态。

共享模块变更后运行 `python tools/sync_pages_robot3d.py`，用 `--check` 检查副本一致性。Pages 发布源为 `main/docs`，合并后等待构建完成。可用 `python -m http.server 8766 --bind 127.0.0.1 --directory docs` 在本地检查静态站点。

2026-09-08 在线预览更新验证：17 项前端测试、22 项主系统测试、14 项世界模型测试通过；Pages 22 个共享资源与本地源码逐字节一致。浏览器已检查模型与两路画面、30°关节/50%夹爪输入、轨迹播放锁定输入及停止/重置、模拟只读反馈、断开状态和 390 px 窄屏布局。测试服务无硬件 SDK，未发送真机或夹爪动作；这些检查不提供实机对齐精度证据。

正常使用：按原来的后端启动方式运行，打开 `http://127.0.0.1:8001/ui/`。默认进入手动预览，Three.js 和 GLB 均为本地资源，不需要 npm 安装、构建或 CDN。

完全无硬件验证：在项目根目录执行 `python tools/robot3d_dev_server.py`，打开 `http://127.0.0.1:8765/ui/?apiBase=http://127.0.0.1:8765`。该测试服务仅绑定回环地址，不导入 SDK，所有 POST 返回 405；勿使用真机启动脚本做此项验证。Python 标准库即可运行这个测试服务。

- 拖动、滚轮、右键分别调整自由观察视角；“视角复位”和“居中观察”只移动相机。
- 六个关节输入采用度，允许 ±180°，这是展示范围而非真机限位。夹爪为 0～100% **动画进度**，不是毫米开口。
- 手动输入、轨迹播放、只读反馈由一个姿态状态对象管理。轨迹播放时禁止手动编辑；切换模式、换模型、重置、销毁均停止轨迹。停止保留最后预览姿态，重置回到模型导入零位。
- 动作格式示例：`关节1:30,关节2:-30,夹爪:100;关节1:0,关节2:0,夹爪:0;`。每段时长 100～60000 ms，最多 100 段。整段序列先校验再播放；拒绝空值、非有限数、非法字符、重复关节和越界目标。没有速度/加速度规划或碰撞保证。
- “实时反馈”只调用现有 `GET /api/robot/status`，复用已有后端地址和当前令牌，默认串行轮询，完成后间隔 1000 ms。与控制台“自动刷新”互相独立，控制台总览刷新不会写入三维姿态。
- 反馈关节按六个弧度数处理，超出手动滑块范围的有限反馈不截断。没有夹爪反馈，因此此模式仅显示夹爪动画零位，并明确标注未知。
- “场景配置”编辑桌面、目标物、示意相机及手动姿态；位置/尺寸均为 Base 坐标系下的米，角度为弧度。应用前整体校验。可以本地保存/恢复、JSON 导出/导入。恢复不会自动进入实时模式。令牌、反馈和上传的 GLB 不进入场景文件。

浏览器需支持 ES modules、WebGL、ResizeObserver。自动验证使用 Node 24 与 Python 3.14；后端环境安装参见项目主 README。

## 结构与接口

目录：`robot_system/web/static/robot3d/`。

| 文件 | 职责 |
| --- | --- |
| `index.js` / `panel.css` | 三维面板交互与生命周期；从 app.js 注入只读请求函数 |
| `scene.js` | 场景、桌面、目标物、自由观察相机、缩放与渲染 |
| `model-loader.js` | 自包含 GLB 检查、最新请求提交、失败恢复、资源释放 |
| `joints.js` | 六关节初始变换保存、局部轴四元数叠加、夹爪动画白名单 |
| `state.js` / `trajectory.js` | 独立数值姿态、单一姿态来源、时间插值与停止 |
| `sync.js` | 串行只读轮询、超时、请求代际、来源和时间状态 |
| `virtual-camera.js` | 与自由相机独立的示意相机和相机位置标记 |
| `coordinates.js` / `validation.js` | 坐标方向、TCP 欧拉约定、单位边界和输入校验 |
| `config.js` | version=1 场景、校验、持久化 |
| `assets/frames.json` | 坐标定义、变换方向、单位、来源与校准状态 |

后端仅为原状态响应添加三个字段：`feedback_read_at_unix_ms`（整数 Unix 毫秒）、`feedback_time_source=server_read_completion`、`joint_unit=radian`；响应增加 `Cache-Control: no-store`。这是 SDK 读取完成时间，**不是控制器硬件采样时间**。底层只读控制器仍禁用自动使能和夹爪初始化。

反馈超过 3500 ms 显示过期；请求超时为 3000 ms；重复/倒退时间戳、未来超过 1000 ms 的时间戳、格式异常、非连接状态、HTTP 错误均明确提示。旧后端没有时间戳时显示“实时性未验证”。客户端和服务端需时钟一致，否则会保守判为异常。`dry_run=true` 始终显示模拟反馈，不宣称真机同步。断开/过期保留本来源最后有效姿态；首次未收到有效反馈则隐藏机械臂。修改后端地址/令牌会丢弃旧来源的请求和姿态。

虚拟画面使用独立相机、640×360 渲染目标，最多每秒 10 帧，通过同一个 WebGL renderer 读取像素并复制到独立画布；自由观察不会改变此相机。低性能设备的实际帧率可能更低。场景中的青色相机标记表示示意相机的位置与方向，标记尺寸不代表真实设备尺寸。实际相机远裁面为 30 m。

## 模型和坐标核对

资源由用户提供的 GitHub 仓库取得，精确提交、路径、哈希与许可情况见 `assets/SOURCES.md`。参考站直接下载失败，不能断言两个站点二进制逐字节相同。

运行 `node tools/inspect_robot_model.mjs` 可再生成 `assets/model-inspection.json`：

- 二进制大小 3,376,080 bytes，glTF 2.0，73 个节点，无外部 buffer、图片或压缩解码器依赖。
- 根节点 `lebairobot`，其下 `Joint1 → Joint2 → Joint3 → Joint4 → Joint5 → Joint6` 连续串联。六关节导入旋转均为单位四元数、缩放均为 1；关节位置及全部网格、夹爪层级初始变换保留。
- 初始包围盒尺寸约 `[0.142617, 0.903972, 0.425571]` m（模型 X/Y/Z，包含夹爪及模型自带相机支架），是网格数值，未作为真机尺寸测量。
- 关节参考局部轴依次为 `[Y,Z,Z,Z,Y,Z]`。运动公式为 `Q_import × Q_axis(direction × q_sdk + zeroOffsetRad)`。方向暂为 +1、偏置暂为 0，**都待实测**。导入安装变换不会被 Euler 分量覆盖。
- `Take 001` 动画 9.5 s，6 条四元数轨道，各 229 个关键帧，只涉及夹爪。按参考展示区间使用 0～第20关键帧，即 0～0.833333 s；比例表示该区间的动画进度，未测量开口。白名单轨道不会覆盖 Joint1～Joint6。

变换使用 `A_T_B` 命名，含义为 `p_A=A_T_B*p_B`，列向量、JSON 矩阵逐行存储。内部米/弧度/毫秒，glTF 动画时间为秒并在动画边界转换。Base 为右手 Z-up，Three 场景为 Y-up：`scene_T_base=Rx(-π/2)`。模型 Y-up 到 Base 暂用 `base_T_model=Rx(+π/2)`，平移0、尺度1；这是显示约定，尚未建立实测 Base 对应关系。包围盒居中只改观察相机，不改模型物理坐标。

TCP 使用后端字典 `x,y,z,rx,ry,rz`，`R=Rz*Ry*Rx`；有单独转换函数及验证。没有模型法兰到 TCP 的标定，未用 `Joint6` 冒充真实 TCP。OpenCV 光学相机 X右/Y下/Z前；Three 相机看向 -Z，二者转换为 `Rx(π)`。后续标定相机应组合 `scene_T_base * base_T_camera * optical_T_threeCamera`，并从核对后的内参构建投影。

## 相机标定边界

以下是开发工作区自有标定文件的历史数值核对结果；没有上传该设备的原始标定或审计指纹。仓库示例标定不代表实际设备，不能用于真实对齐：

- 当前 `biaoding/eye_to_hand_result.json` 中 RGB 内参来源为 preset，矩阵和 1280×720 图像尺寸与 Orbbec INI 一致。
- 外参旋转行列式为 1，`base_T_camera * camera_T_base` 的数值误差约 6.66e-16，仅表示矩阵互逆，**不是定位精度**。
- 畸变系数非零；真实视图对齐还需处理畸变、图像裁剪/缩放、设备身份和实际流尺寸。
- INI 文件名标为深度848×480，但文件内容是854×480。未打开硬件验证此差异。
- 当前模型 Base、关节零位/符号、TCP 都未实测，故仅开放示意相机；导入配置请求 `camera.mode=calibrated` 会明确拒绝。没有报告任何真实像素或毫米对齐精度。

## 验证命令与范围

```powershell
node --test tests/frontend/robot3d.test.mjs
python -m unittest discover -s tests -p test_robot3d_status.py -v
python -m unittest test_safety_hardening test_probe_lock_flow -q
node tools/inspect_robot_model.mjs
```

自动验证覆盖单位/坐标变换、导入旋转叠加、实际 GLB 与夹爪隔离、空值/Infinity/越界校验、独立轨迹状态、停止/重置、模式切换、时间与来源、迟到反馈丢弃、异步模型先后顺序/失败/销毁、GLB 资源限制、配置版本/保存恢复，以及后端鉴权和只读调用序列。所有测试均使用离线或模拟数据，没有真机动作。

模型替换成功后释放旧 geometry/material/texture 和动画绑定；旧异步结果立即释放，失败保留原模型。加载产生的临时 URL 在解析完成或失败时撤销，导出 URL 在下载后/销毁时撤销。页面销毁停止帧循环、观察器、OrbitControls、轮询、定时器和监听，释放渲染目标与 WebGL 上下文；bfcache 恢复会重载。

已知限制：只接收 ≤50 MiB 的自包含 GLB 2.0，必须具有唯一的 Joint1～Joint6 连续层级；不支持多文件 glTF、Draco/KTX2/Meshopt 必需扩展。外部模型的物理比例和轴映射不自动识别；只有同名夹爪专用轨道可预览。外部 GLB 不被持久化，保存配置前需恢复内置模型。不包含自动场景重建、IK 求解、接触动力学、碰撞检查、抓取验证或真机自动执行。浏览器验证覆盖模型加载、45°关节输入、0.5°小数输入、181°错误提示、轨迹停止/重置、模拟反馈与过期/断开、坏GLB保留原模型、场景保存恢复、自由相机拖动及390px窄屏。自由视角拖动前后虚拟相机截图区域像素差为0，这仅验证渲染独立性。没有报告真实对齐精度。
